演进路线图（对应之前讨论的 P0 / P1 / P2）

P0 基础丰富度（一轮可做）

  • 字体族 / 字号 / 字体颜色 / 高亮
  • 上标 / 下标
  • 段落缩进（增减）
  • 3×3 表格 + 表内加行/列/合并
  • 字数统计

P1 像 Outlook 的体感（一轮可做）

  • 签名 + 默认模板自动插入
  • 表情面板
  • 格式刷
  • 查找 / 替换
  • 粘贴三档（保留 / 合并 / 纯文本）
  • 图片拖拽改尺寸

P2 邮件专属（需改 MIME）

  • 图片走 CID 内嵌附件（替换 data URL）
  • 发送前 HTML 归一化 + 兼容性提示
  • HTML 源码视图（本演示已可点）
  • 表格导出为内联样式兼容 Outlook

说明：模拟界面用浏览器原生 contentEditable 实现，逻辑与 App 里的 Tiptap 编辑器等价（加粗→<strong>、表格→<table> 等）。 真正的 App 里，图片/链接走内联地址条而非 window.prompt（Electron 渲染进程不实现 prompt）； 正文在发送前会过主进程 sanitizeComposeHtml() 权威净化。三个必须接受的邮件约束：① Outlook 桌面版不支持 flex/grid，依赖内联样式； ② 不能用 <style> 块；③ 截图目前内联成 base64，正式版走 CID。
